1. **[src/lib/immigration/daily.ts:119](file:///Users/jeong-ilin/study/dailybit/src/lib/immigration/daily.ts#L119) — Quiet-day early return skips `q.flush()`, dropping queued `saveSeen` and `saveSnapshot` writes**
   - **Why:** `deferMonitorStore` ([daily.ts:41](file:///Users/jeong-ilin/study/dailybit/src/lib/immigration/daily.ts#L41)) and `deferCommunityStore` ([daily.ts:49](file:///Users/jeong-ilin/study/dailybit/src/lib/immigration/daily.ts#L49)) defer all `saveSnapshot` and `saveSeen` calls into `q.ops`. When there are new IRCC/CIC News articles that Claude summarizes as all `relevant: false`, `runNewsDigest` ([news-digest.ts:71-91](file:///Users/jeong-ilin/study/dailybit/src/lib/immigration/news-digest.ts#L71-L91)) posts 0 notes and queues `saveSeen` so those articles are not re-evaluated tomorrow. Similarly, `checkPage` ([monitor.ts:136-141](file:///Users/jeong-ilin/study/dailybit/src/lib/immigration/monitor.ts#L136-L141)) queues `saveSnapshot` with 0 notes when a watched page is `"new"` (initial seed) or `"same"` (`checkedAt` update). When `q.notes === 0 && errors.length === 0`, line 119 returns before calling `q.flush()`, discarding every queued save—so irrelevant news articles remain unseen and are re-sent to Claude every quiet day until a day produces a note, and watched-page snapshots are never persisted on quiet days. (In [daily.test.ts:81-87](file:///Users/jeong-ilin/study/dailybit/src/lib/immigration/daily.test.ts#L81-L87), the first run only saved `seen` because unseeded draws queued 3 backfill notes in the same run.)
   - **Fix:** Flush queued save operations before returning on a quiet day (`await q.flush(deps.post); return { ...r, notes: 0 };` — when `q.notes === 0`, `flush` executes only the queued `save` callbacks without calling `deps.post`).

   - **Why:** `errors` ([daily.ts:100-108](file:///Users/jeong-ilin/study/dailybit/src/lib/immigration/daily.ts#L100-L108)) only captures uncaught exceptions thrown out of `runMonitor`, `runNewsDigest`, or `runCommunityDigest`. However, `runMonitor` and `runNewsDigest` catch their own failures and return structured error states with `0` notes instead of throwing: AI failure sets `news.summarized = false` ([news-digest.ts:77-81](file:///Users/jeong-ilin/study/dailybit/src/lib/immigration/news-digest.ts#L77-L81)), RSS failure sets `feed.error` ([news-digest.ts:53-55](file:///Users/jeong-ilin/study/dailybit/src/lib/immigration/news-digest.ts#L53-L55)), and draw/page fetch failure sets `program.error` or `page.status = "error"` ([monitor.ts:85-87](file:///Users/jeong-ilin/study/dailybit/src/lib/immigration/monitor.ts#L85-L87), [monitor.ts:129-132](file:///Users/jeong-ilin/study/dailybit/src/lib/immigration/monitor.ts#L129-L132)). On any day without new draws (`q.notes === 0`), `errors.length` is also `0`, so line 119 returns early without posting `dailyHeader` (contradicting [daily.ts:69-79](file:///Users/jeong-ilin/study/dailybit/src/lib/immigration/daily.ts#L69-L79) and [.github/workflows/immigration.yml:45](file:///Users/jeong-ilin/study/dailybit/.github/workflows/immigration.yml#L45)).
   - **Fix:** Check for structured step failures in addition to `errors.length > 0` (e.g. `const hasFailure = errors.length > 0 || Boolean(r.monitor?.programs.some((p) => p.error) || r.monitor?.pages.some((p) => p.status === "error") || r.news?.feeds.some((f) => f.error) || (r.news && !r.news.summarized) || (r.weekly && (!r.weekly.summarized || r.weekly.listed === 0)));`) and only skip posting the header when `q.notes === 0 && !hasFailure`.

3. **[src/lib/immigration/daily.ts:70-73](file:///Users/jeong-ilin/study/dailybit/src/lib/immigration/daily.ts#L70-L73), [src/lib/immigration/daily.ts:122](file:///Users/jeong-ilin/study/dailybit/src/lib/immigration/daily.ts#L122) — `"no draws parsed"` layout failure is excluded from `failed` and misreported in `dailyHeader` as `"새 소식 1건"` or `"변화 없음"`**
   - **Why:** When a draw table page returns 200 HTML with 0 parsed rows ([monitor.ts:88-99](file:///Users/jeong-ilin/study/dailybit/src/lib/immigration/monitor.ts#L88-L99)), `checkProgram` sets `error: "no draws parsed"` and queues a layout-warning note throttled to once every 7 days (`WARN_EVERY_MS`). Because line 70 filters out `p.error !== "no draws parsed"`, the broken program is omitted from `(못 읽음: ...)`. On day 1 (when the warning note is posted), `monitor.notes` counts the warning note in `counts.monitor`, so line 73 reports `- 선발·공지: 새 소식 1건` ("1 new item") for a parse failure. On days 2–7 (while `WARN_EVERY_MS` suppresses the warning note), `counts.monitor` is `0` and `fail` is empty, so line 73 reports `- 선발·공지: 변화 없음` ("no change") even while [scripts/immigration.ts:69](file:///Users/jeong-ilin/study/dailybit/scripts/immigration.ts#L69) exits `1`.
   - **Fix:** Include `"no draws parsed"` in `failed` (`r.monitor.programs.filter((p) => p.error).map((p) => LABEL[p.program])`), and compute `counts.monitor` from actual draw/page update notes (`r.monitor.programs.filter((p) => p.added > 0).length + r.monitor.pages.filter((p) => p.status === "changed").length`) rather than total `monitor.notes`.

4. **[src/lib/immigration/daily.ts:101-109](file:///Users/jeong-ilin/study/dailybit/src/lib/immigration/daily.ts#L101-L109) — `step()` does not roll back `q.ops` when a step throws mid-execution**
   - **Why:** `runMonitor` ([monitor.ts:160-169](file:///Users/jeong-ilin/study/dailybit/src/lib/immigration/monitor.ts#L160-L169)) iterates through `EE`, `BC_PNP`, `AAIP`, and `WATCHED_PAGES`, calling `settle(p)` (which queues `note` and `save` into `q.ops`) after each item before performing store reads (`existingKeys` / `getSnapshot`) for the next item. If an earlier program queues its note and save and a subsequent store read in the same step throws, `step()` catches the error and sets `monitor.value = null`, so `dailyHeader` ([daily.ts:74](file:///Users/jeong-ilin/study/dailybit/src/lib/immigration/daily.ts#L74)) prints `- 선발·공지: 실행 실패` while `q.flush()` still posts and saves the partially queued operations from the failed step.
   - **Fix:** Record `const beforeOps = q.ops.length` before `await run()`, and in the `catch` block truncate `q.ops.length = beforeOps` and return `{ value: null, notes: 0 }`.

5. **[.github/workflows/immigration.yml:46-58](file:///Users/jeong-ilin/study/dailybit/.github/workflows/immigration.yml#L46-L58) — `continue-on-error: true` on `Check Claude CLI auth` hides broken Claude auth on days with no unseen articles**
   - **Why:** `Check Claude CLI auth` sets `continue-on-error: true` so draw alerts still run, relying on `Daily digest` to exit `1` when AI fails (line 45). On any day with 0 new RSS items, `summarize()` is never called, `n.summarized` stays `true`, and `scripts/immigration.ts` exits `0`—so the workflow run succeeds green despite `Check Claude CLI auth` failing.
   - **Fix:** Add `id: auth` to `Check Claude CLI auth` and either pass its outcome into `Daily digest` or add a post-digest step (`if: steps.auth.outcome == 'failure'`, `run: exit 1`) so the job still fails after draw alerts are posted.
