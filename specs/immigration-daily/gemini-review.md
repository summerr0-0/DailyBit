   - **Why:** `deferMonitorStore` ([daily.ts:41](file:///Users/jeong-ilin/study/dailybit/src/lib/immigration/daily.ts#L41)) and `deferCommunityStore` ([daily.ts:49](file:///Users/jeong-ilin/study/dailybit/src/lib/immigration/daily.ts#L49)) defer all `saveSnapshot` and `saveSeen` calls into `q.ops`.    - **Why:** When a draw table page returns 200 HTML with 0 parsed rows ([monitor.ts:88-99](file:///Users/jeong-ilin/study/dailybit/src/lib/immigration/monitor.ts#L88-L99)), `checkProgram` sets `error: "no draws parsed"` and queues a layout-warning note throttled to once every 7 days (`WARN_EVERY_MS`). 4. **[src/lib/immigration/daily.ts:101-109](file:///Users/jeong-ilin/study/dailybit/src/lib/immigration/daily.ts#L101-L109) — `step()` does not roll back `q.ops` when a step throws mid-execution**
   - **Why:** `runMonitor` ([monitor.ts:160-169](file:///Users/jeong-ilin/study/dailybit/src/lib/immigration/monitor.ts#L160-L169)) iterates through `EE`, `BC_PNP`, `AAIP`, and `WATCHED_PAGES`, calling `settle(p)` (which queues `note` and `save` into `q.ops`) after each item before performing store reads (`existingKeys` / `getSnapshot`) for the next item.    - **Fix:** Record `const beforeOps = q.ops.length` before `await run()`, and in the `catch` block truncate `q.ops.length = beforeOps` and return `{ value: null, notes: 0 }`.
